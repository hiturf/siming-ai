# 司命 3.3.2

3.3.2 不是一次只有少量补丁的修复版，而是一次覆盖模型路由、Agent 执行架构、作者可控写作流程、Android 独立建档和跨端可靠性的集中升级。相较 `v3.3.1`，本版本共变更 497 个文件，新增 32,280 行、删除 45,242 行。

## Android 安装包刷新（2026-08-27）

- 手机独立助手改为直接消费 Chat Completions / Responses API 的真实 SSE 增量，正文、可见推理与函数参数不再等待整段响应后模拟分片；对话式立项同样使用真实流式输出。
- Gateway 助手新增会话历史、运行 ID、工具日志、显式 Operation 取消和断流后按持久化 Run 恢复；手机独立会话与工具日志也可跨重启恢复。
- AI 新章节只进入正文草稿编辑器，生成中实时显示正文；完成后由作者明确选择“仅保存”或“保存并建档”，助手提示文字不再能被误存成章节。
- 手机在线导入补齐 DOCX 文件选择并复用 PC 权威导入接口；离线仍只解析 TXT，界面会明确说明限制。
- 本次只刷新 Release 中的 `Siming.apk` 与 `Siming-apk-sha256.txt`；`v3.3.2` tag 和 Windows 安装资产保持不变，APK 由 `main` 的已验证提交使用原发布密钥重新签名。

## 主要更新

### 可用模型目录与按任务选择模型

- API、OpenAI 兼容服务、本机 Agent CLI 和本地模型运行时会保存真实获取到的可用模型目录，不再只记录一个默认模型名。
- 系统设置新增统一的“按任务选择模型”，可分别为项目助手、立项与规划、作品建档、章节写作、质量评估和拆书分析指定模型。
- 任务模型可以跨 API、CLI 与本地模型选择；统一优先级为“本次任务明确选择 > 任务默认 > 全局默认”。
- PC 端立项、项目助手、建档、写作、质量评估、角色专用模型和拆书入口均从真实可用模型目录选择，并自动跟随对应任务默认值。
- Android 直连 API 同样支持自动获取模型列表，并可为上述六类任务分别保存模型，不依赖 PC 端代选。
- 本地模型可按任务单独设置上下文长度；超过模型容量时会明确拒绝保存，不再静默缩短。
- 修复模型身份在立项对话、结构化生成、作品建档和本机 CLI 任务中的传递，确保界面所选模型就是实际执行模型。

### 统一 Agent 工作流与工具权限

- PC GUI、API、本机 CLI、MCP 和 Android 使用同一套权威工具目录、任务状态和权限边界，不再为不同入口维护重复的 Agent 业务路径。
- 每个 Agent 回合先只开放 `set_tool_categories`，由模型根据用户最新消息选择下一步所需的宽粒度工具类别；运行时再与当前授权及真实工具注册表取交集。
- 删除旧的关键词/正则意图路由、旧 Planner、旧 Blueprint 和重复写作服务；自然语言意图、目标实体和工具选择统一交给当前模型结合真实项目数据判断。
- 应用层只负责校验项目归属、实体类型、参数、权限、事务、幂等、并发和回合终止，避免界面选中项或历史对话暗中覆盖用户最新要求。
- 接口报错、工具协议中断、空工具流和结构化输出失败会如实停止并给出诊断，不再静默切换到另一条文本执行路径。
- OpenAI 兼容 API 新增 Chat Completions、Responses API 与自动识别选项，并补强流式工具调用和结构化输出兼容性。

### 本机 Agent CLI 工具桥

- Claude Code、Codex CLI、OpenCode、Mimo Code、Cursor Agent、Kilo Code、Qwen Code、Hermes、OpenClaw 和 DeepSeek Harness（DSH）统一使用当前回合临时创建的 `siming_turn` MCP。
- 临时 MCP 只绑定当前作品或立项任务，CLI 退出后自动失效，不修改 CLI 的全局 MCP 配置，也不再解析终端文本中的 JSON 工具指令。
- 本机 CLI 与 API 使用同一工具类别、授权、项目归属和写入契约，修复“模型能对话但不能真实调用项目工具”的情况。
- OpenCode 快速开始会读取本机 CLI 的实时模型目录，优先选择当前仍可用的免费模型；可选地将 OpenCode 加入当前用户 PATH，无需管理员权限。
- 新增 DSH 正式接入，并保留各 CLI 的真实模型身份、推理内容、工具调用和错误诊断。

### 作者可控的立项与章节草稿

- AI 生成的新章节始终先进入独立的未保存草稿，不能覆盖或伪装成任何已保存章节，也不能把卷级、场景级节点当作章级目标。
- 未保存草稿存在时，编辑器以草稿为唯一正文来源；旧章节的迟到请求会被取消或忽略，不再回写覆盖新草稿。
- 草稿生成成功即结束模型回合。是否“保存并建档”或“仅保存”、何时继续下一章，全部由作者明确决定。
- PC 与 Android 的写章流程都增加持久检查点、断流续传、取消状态和重复请求防重；手机端可从已保存文字检查点继续生成。
- 立项会话统一使用 V3 结构化 Artifact；对话、阶段生成、编辑、确认、最终审阅和正式建档都读写同一份草稿。
- 修复只读 Artifact 序列化意外修改会话时间戳的问题，使无效补丁校验与下游影响报告保持原子性。

### Android 独立建档与模型设置

- 新增完整的新书建档工作台：阶段导航、创意方向选择、生成/重新生成、按要求调整、完整编辑、确认进入下一项、冲突提示、最终审阅和正式建档。
- 立项对话页与结构化建档页始终共享同一份 V3 草稿；手机独立模式使用由 PC 构建时导出的同源提示词、阶段结构、标准化和依赖失效契约。
- 连接 Gateway 时继续调用 PC 权威建档接口；手机直连模型时使用本机加密保存的 provider 配置，并独立完成完整建档流程。
- 补齐世界观基调、剧情结构、节奏控制和正文风格等字段，使手机正式建档结果与 PC 对齐。
- 手机设置页可查看 API 获取到的模型目录，并分别设置项目助手、立项、建档、写作、评估和拆书模型。

### 作品建档自动补全与一致性

- 建档发现候选缺失时会把精确缺项反馈给模型，并进入增量修复回合，不再清空上一轮有效候选后整章重跑。
- 多轮返回的有效角色、世界观、章节事实和治理候选会累计合并，并按数据库真实候选数继续排序。
- 对世界观标题的说明性括号后缀进行安全归一化；既有设定仅被本章引用时可建立章节关联，不再强迫模型虚构更新。
- 身份未确认的神秘人影、陌生声音等保留为章节线索，不强制创建空白永久角色卡；清单外额外候选改为人工核对警告。
- PC、Gateway、Android 和本机 CLI 共用同一候选校验、自动补全、重试上限与最终写入结果。
- 将 `character_ai_config` 纳入 PC、Gateway 与 Android 共用的同步实体契约，并增加实体注册表与公开同步协议的一致性回归测试。

### Android TXT 导入可靠性与性能

- TXT 导入支持 UTF-8、UTF-8 BOM、UTF-16LE/BE、GB18030 和 Big5 自动识别；无法可靠识别时会明确停止，不再静默写入乱码。
- Gateway 在线时只上传一次原始文件，由后端在单个事务中完成解码、拆章、创建作品与全部章节，并只排队一次同步。
- 离线导入将编码识别和拆章移出主线程，作品、章节与 outbox 在单个 Room 事务中写入，完成后只调度一次同步。
- 章节识别补充序章、楔子、引子、尾声、卷/部、英文 Chapter/Part 和括号标题，并过滤正文中的伪章节标题。
- 单文件限制统一为 20 MiB；异常拆分超过 2,000 章时停止并提示检查章节标题。

### 启动、更新与发布可靠性

- Gateway 同步队列恢复改为非阻塞；单条过期或异常任务会记录日志并保留重试，不再阻止整个桌面应用启动。
- 本地模型目录更新为 Qwen3.5 4B/9B 与 Qwen3.8 27B，并继续支持登记任意现有 GGUF 或 HTTPS 下载地址。
- Windows 更新检查同时查询 GitHub Releases 与 Gitee 镜像；同一版本可由用户明确选择下载源，并始终校验发布清单中的 SHA-256。
- Gitee 同步调整为等待 Release Gate 成功发布后再按精确标签同步，修复镜像发行版长期慢一个版本的问题。
- 正式发布门禁同时覆盖前端、后端、性能、生成 API、Windows 安装冒烟、Android 单元测试与 lint、签名 APK 构建以及四项发布资产校验。
